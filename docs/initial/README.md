## โจทย์ต้นทาง (สรุป)

Final Exam MVP ของนักเรียน Full-Stack: เว็บจองโต๊ะและรีวิวร้านอาหาร ต่อยอดสถาปัตยกรรมและธรรมเนียมจากโปรเจกต์ของคอร์ส `pea-wongnok`
(Go + Gin + GORM + PostgreSQL, Keycloak, Next.js + TypeScript + Tailwind + shadcn/ui, Docker Compose) ทำเฉพาะ MVP เขียนให้อ่านง่าย ทดสอบได้

- **บัญชีเดียวเป็นได้ทั้งเจ้าของร้านและลูกค้า**
- **เจ้าของร้าน:** สร้าง/แก้/ลบร้านของตัวเอง จัดการรายละเอียด รูป จำนวนที่นั่ง เวลาเปิดปิด และเวลาที่ยกเลิกได้ล่วงหน้า (ขั้นต่ำ 30 นาที)
- **ลูกค้า:** เลือกดูร้าน เรียงตามคะแนนเฉลี่ยหรือจำนวนรีวิว จอง/แก้/ยกเลิก/ดูการจองของตัวเอง เขียนรีวิวข้อความพร้อมคะแนนเต็มจำนวน 1–5
- **กฎการจอง (ตรวจใน Go ทั้งหมด):** อยู่ในเวลาเปิด, ห้ามเริ่มย้อนหลัง, จำนวนคนที่อยู่พร้อมกันเกินที่นั่งไม่ได้,
  การแก้ไขไม่นับที่นั่งเดิมของตัวเองซ้ำ, ยกเลิกได้ภายในเวลาที่ร้านกำหนด และคำขอพร้อมกันต้องไม่ทำให้จองเกิน
- **สิทธิ์:** เจ้าของแก้/ลบได้เฉพาะร้านตัวเอง ผู้ใช้จัดการได้เฉพาะการจองของตัวเอง และรีวิวร้านตัวเองไม่ได้
- ผู้ใช้สั่งเพิ่มนอกโจทย์: เจ้าของดูการจองของร้านตัวเอง (อ่านอย่างเดียว), อัปโหลดรูปร้าน, ค้นหาตามชื่อ, ย้ายความลับไปไว้ใน `.env`

## ลำดับที่เอกสารเกิดขึ้น

| ขั้น | ผลลัพธ์ | ไฟล์ |
| --- | --- | --- |
| 1. Brainstorming | ตกลงข้อกำกวมของโจทย์ทีละข้อ เช่น การจองเป็นช่วงเวลาแบบ `[เริ่ม, สิ้นสุด)`, นับคนที่อยู่พร้อมกันสูงสุด, ล็อกแถวร้านตอนจอง, เวลาทั้งหมดเป็น `Asia/Bangkok`, เปลี่ยนชื่อเป็น `bookingtable` | [design.md](design.md) |
| 2. Spec | สังเคราะห์เป็น user stories, ข้อตกลงด้านการออกแบบ และจุดที่ต้องทดสอบ | [SPEC.md](SPEC.md) |
| 3. Plan | แตกเป็นงานย่อยที่ทำตามได้ทีละขั้น: backend 13 งาน (Task 0–12), frontend 10 งาน (Task 0–9) | [Backend_PLAN.md](Backend_PLAN.md), [Frontend_PLAN.md](Frontend_PLAN.md) |
| 4. Implement | ทำเป็นรอบ ผ่าน code-review ทุกรอบ แล้วติดแท็ก (ด้านล่าง) | ประวัติ git |
| 5. หลังแผน | ธีมสี (โทนฟ้าแบบ Facebook), รูปร้านตัวอย่างจาก Unsplash, README, สคริปต์ทดสอบด้วยเบราว์เซอร์, จัดระเบียบโปรเจกต์ | ประวัติ git |

รอบการ implement (แท็กใน git):

| แท็ก | งานที่ครอบ |
| --- | --- |
| `base` | commit แรก: spec และแผนเท่านั้น (ยังไม่มีโค้ด; โค้ดต้นแบบถูกคัดลอกเข้ามาใน Backend Task 0) |
| `b1-done` … `b4-done` | Backend Task 0–2, 3–5, 6–9, 10–12 |
| `f1-done` | Frontend Task 0–2 (ตรรกะใน `web/lib`: เวลา, error, เวลาเปิด, API client + refresh token) |
| `f2-done` | Frontend Task 3–9 (หน้าทั้งหมดและการตรวจด้วยเบราว์เซอร์) |

## เอกสารอ้างอิงจากคอร์ส

[reference/](reference) คือเอกสารสถาปัตยกรรมของโปรเจกต์ต้นแบบ `pea-wongnok` ที่โจทย์ให้อ่านก่อนทำ
(ระบบ [SYSTEM](reference/SYSTEM_ARCHITECTURE.md), [BACKEND](reference/BACKEND_ARCHITECTURE.md), [FRONTEND](reference/FRONTEND_ARCHITECTURE.md))
**ไม่ใช่เอกสารของแอปนี้** ชื่อ package ตาราง และ endpoint ในนั้นเป็นของต้นแบบ เก็บไว้เพราะ spec และ plan อ้างถึงธรรมเนียมการเขียนโค้ดของมัน

## จุดที่เอกสารเหล่านี้ต่างจากของจริง

อ่านเป็นประวัติได้ แต่อย่าทำตามคำสั่งเหล่านี้ตรง ๆ:

- `Backend_PLAN.md` อ้าง `docs/API.md` แต่ไฟล์จริงคือ `api/docs/API.md`
- `Backend_PLAN.md` แนะนำให้เพิ่ม `keycloak` ใน `/etc/hosts` ซึ่งผิด (พอร์ต 8080 คือ API) ของจริงใช้ `keycloak.localhost:8180` กับ `extra_hosts` ใน `compose.yml`
- `SPEC.md` เขียนว่าโปรเจกต์ไม่ใช่ git repo และยังไม่ตั้งค่า issue tracker (ตอนนี้เป็น git repo แล้ว ไม่ใช้ issue tracker)
- `Frontend_PLAN.md` ตั้ง script `typecheck` เป็น `tsc --noEmit` ของจริงเป็น `next typegen && tsc --noEmit` และใช้ฟอนต์ Geist ของจริงใช้ Noto Sans Thai
- ธีมสีในแผนยังเป็นของ template (ม่วง) ของจริงเป็นโทนฟ้าแบบ Facebook แล้ว
- ข้อความที่ระบุตัวเลขหรือรายการสถานะ (เช่น "รอผู้ใช้ตรวจไฟล์" ใน `design.md`) เป็นสถานะ ณ ตอนนั้น
