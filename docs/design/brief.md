# Design brief: Table Not Found

> **โจทย์ที่ส่งให้ Claude Design ก่อนออกแบบใหม่ (เก็บไว้เป็นส่วนของชุดส่งดีไซน์)** ดีไซน์ที่นำเข้าเว็บแล้วและกติกาปัจจุบันอยู่ใน [DESIGN.md](../../DESIGN.md) ที่ root ข้อความในไฟล์นี้ที่พูดถึงหน้าตาเดิม (สีฟ้า Facebook, ช่องเวลา, ภาพ `screens/` ชุดแรก) ไม่ตรงกับโค้ดแล้ว

*Find a table. Find your food.*

เว็บจองโต๊ะและรีวิวร้านชาบู/ปิ้งย่างในประเทศไทย ทำงานได้ครบแล้ว (จอง แก้ ยกเลิก รีวิว จัดการร้าน) **สิ่งที่ขอคือออกแบบหน้าตาให้ดีขึ้น** ไม่ใช่เพิ่มฟีเจอร์
เอกสารนี้ใช้คู่กับ `screens/` (ภาพหน้าจอปัจจุบัน), `tokens.md` (สีและ component ที่มี) และ `assets/` (ไอคอน รูปตัวอย่าง)

## 1. แอปนี้คืออะไร

- **ผู้ใช้:** คนทั่วไปที่หาร้านและจองโต๊ะ (ลูกค้า) และเจ้าของร้านที่ลงร้านและดูการจอง บัญชีเดียวทำได้ทั้งสองบทบาท ไม่มีหน้าแยกบทบาท
- **ภาษา:** ไทยทั้งหมด (ชื่อแอปและ tagline เป็นอังกฤษ) เวลาทุกอย่างเป็นเวลาประเทศไทย
- **อุปกรณ์:** ใช้ทั้งมือถือและเดสก์ท็อป (เนื้อหากว้างสูงสุด 1024px)
- **บริบท:** งานสอบ Final ที่ต้องเดโมให้กรรมการดู จึงต้องดูเรียบร้อยและน่าเชื่อถือตั้งแต่หน้าแรก

## 2. ทิศทางที่ขอ (ร่างจากแบรนด์ แก้ได้ทั้งหมด)

> **ส่วนนี้ผมร่างให้ ยังไม่ได้ผ่านเจ้าของงาน** แก้ประโยคตรงนี้ได้เลยก่อนส่ง

- สะอาด อบอุ่น น่าไว้ใจ เหมือนแอปจองร้านอาหารที่ใช้ง่าย ไม่ใช่แดชบอร์ด
- คงสีฟ้าเป็นสีแบรนด์ (ตอนนี้ฟ้าแบบ Facebook `#0866ff`; ไอคอนแอปใช้ `#1262ee`) จะปรับเฉดหรือเพิ่มสีรองได้ถ้าช่วยให้ดูอบอุ่นขึ้น
- ชื่อ "Table Not Found" เป็นมุกเล็ก ๆ จะใส่บุคลิกขี้เล่นได้เฉพาะจุดที่ไม่รบกวนการใช้งาน เช่น หน้า 404 และช่วงที่ที่นั่งเต็ม
  (เจ้าของงานเลือกให้ข้อความทั้งหมดเป็นไทยล้วน มีอังกฤษเฉพาะชื่อแอป tagline และหัวข้อหน้า 404)
- ให้รูปอาหารเป็นพระเอก: ตอนนี้การ์ดร้านและหน้าร้านใช้รูปแต่ยังไม่ได้ใช้ให้เต็มที่

## 3. หน้าทั้งหมด (10 หน้า) และภาพอ้างอิง

| หน้า (route) | ใครเห็น | ทำอะไรได้ | ภาพใน `screens/` |
| --- | --- | --- | --- |
| `/` ก่อนล็อกอิน (Landing) | ทุกคน | อ่านว่าแอปทำอะไร กดเข้าสู่ระบบ | `01-landing`, `m01-landing` |
| `/` หลังล็อกอิน (หน้าแรก) | ผู้ล็อกอิน | ค้นหาร้านตามชื่อ เรียงตามคะแนน/รีวิว เปลี่ยนหน้า เห็นการจองถัดไปและร้านคะแนนสูง | `03-home`, `04-home-search-empty`, `18-home-loading`, `19-home-error`, `m02-home` |
| `/restaurants/[id]` | ผู้ล็อกอิน | ดูร้าน เลือกวัน ดูช่วงว่างรายชั่วโมง จอง ดูและเขียนรีวิว | `05a`…`05c`, `13`, `06` (มุมมองเจ้าของ), `m03-restaurant` |
| `/my/reservations` | ผู้ล็อกอิน | ดู แก้ ยกเลิกการจองของตัวเอง | `10`, `10b`, `15` (ว่าง) |
| `/my/profile` | ผู้ล็อกอิน | ดูข้อมูล แก้คำแนะนำตัว ดูสถิติและรีวิวของตัวเอง | `07`, `17` (ว่าง), `m04-profile` |
| `/my/restaurants` | เจ้าของ | ดูร้านของตัวเอง สรุปจำนวน/รีวิว/คะแนน ไปแก้ ดูการจอง ลบ | `08`, `16` (ว่าง), `m05-my-restaurants` |
| `/my/restaurants/new` และ `/my/restaurants/[id]/edit` | เจ้าของ | กรอกชื่อ ที่อยู่ ที่นั่ง เวลาเปิดรายวัน อัปโหลดรูป | `11`, `12`, `m07-restaurant-form` |
| `/my/restaurants/[id]/reservations` | เจ้าของ | ดูการจองของร้านพร้อมสถิติ กรองสถานะ (อ่านอย่างเดียว) | `09`, `m06-owner-reservations` |
| `/auth/callback` | ทุกคน | หน้ารอสั้น ๆ ตอนล็อกอิน (ไม่ต้องออกแบบ) | — |
| 404 | ทุกคน | กลับไปหน้าร้านทั้งหมด | `02-not-found` |

ชื่อไฟล์เลขนำหน้า (`05a`, `05b`, `10b`) คือสถานะย่อยของหน้าเดียวกัน ภาพทั้งหมดใช้ข้อมูลทดลอง (ชื่อและร้านสมมติ ร้านตัวอย่างมีรูปจริงจาก Unsplash)

## 4. สถานะที่ต้องออกแบบ (นอกจากหน้าปกติ)

- **กำลังโหลด** (skeleton): `18-home-loading`
- **ผิดพลาด** พร้อมปุ่มลองอีกครั้ง: `19-home-error`
- **ว่างเปล่า**: ไม่มีร้านที่ค้นหา, ยังไม่มีการจอง, ยังไม่มีร้าน, ยังไม่ได้รีวิว, ร้านยังไม่มีการจอง
- **ช่วงเวลาในตารางช่วงว่าง 4 แบบ:** ว่าง, ใกล้เต็ม (เหลือไม่เกิน 30%), เต็ม (กดไม่ได้), ผ่านไปแล้ว (จาง กดไม่ได้) และวันที่ร้านปิด (`13`)
- **จองไม่สำเร็จ** (ที่นั่งไม่พอ/นอกเวลาเปิด) ในฟอร์มจอง: `05c`
- **สถานะการจอง:** ยืนยันแล้ว / ยกเลิกแล้ว

## 5. ข้อมูลที่มีจริง (อย่าออกแบบจากข้อมูลที่ไม่มี)

ร้านมีเพียง: ชื่อ ที่อยู่ คำอธิบาย (ไม่บังคับ) รูปเดียว จำนวนที่นั่ง เวลาเปิดรายวัน เวลายกเลิกล่วงหน้า (นาที) ชื่อเจ้าของ คะแนนเฉลี่ยและจำนวนรีวิว
**ไม่มี:** ประเภทอาหาร ราคา แท็ก แผนที่/พิกัด เบอร์โทร หลายรูป ระยะทาง ถ้าดีไซน์ต้องการ ให้ระบุว่า "ต้องเพิ่มข้อมูลฝั่ง backend" แยกไว้ ไม่ปนกับงานหน้าตา
รีวิวมีดาว 1–5 กับข้อความ ผู้จองเลือกวันที่และเวลาเริ่ม/สิ้นสุดกับจำนวนคนเท่านั้น (ไม่มีเลือกโต๊ะ)

## 6. จุดที่เห็นว่าควรดีขึ้นในดีไซน์ปัจจุบัน

(จากภาพใน `screens/` ผมเห็นเอง ไม่ใช่ข้อกำหนด เพิ่มหรือค้านได้)

1. **หัวเว็บบนมือถือ** ตกเป็น 3 แถว (โลโก้ / เมนู / ชื่อผู้ใช้กับปุ่มออกจากระบบ) กินที่และดูรก (`m02-home`)
2. **หน้าร้านยาว** ลำดับเป็น ข้อมูลร้าน → ช่วงว่าง → ฟอร์มจอง → เวลาเปิด (ตาราง 7 แถว) → รีวิว ฟอร์มจองกับช่วงว่างยังเป็นสองส่วนที่ต่อกันหลวม ๆ
3. **ช่องกรอกสูงไม่เท่าปุ่ม** (ช่อง 32px ปุ่ม 40px ในแถวค้นหา) และ `select` เป็นของเบราว์เซอร์
4. **หน้าเจ้าของร้านเป็นตารางเรียบ ๆ** (`09`) และหน้า "ร้านของฉัน" ใช้การ์ดเดียวกับลูกค้า ยังไม่สื่อว่านี่คือเครื่องมือจัดการ
5. **การ์ดสถิติ** เป็นตัวเลขสีฟ้าใหญ่ ๆ ทุกใบเหมือนกัน แยกความสำคัญไม่ออก
6. **ฟอร์มวันที่เป็นของเบราว์เซอร์** (`dd/mm/yyyy`) ทั้งที่หน้าเป็นไทย
7. **หน้าแรกหลังล็อกอิน** มีหลายส่วนซ้อนกัน (ทักทาย → การจองถัดไป → คะแนนสูงสุด → ทั้งหมด) ลำดับความสำคัญยังไม่ชัด
8. **หน้า login ของ Keycloak** (ที่ผู้ใช้ต้องผ่านก่อนเข้าแอป) เป็นธีมเริ่มต้นของ Keycloak ไม่เข้ากับแบรนด์ (นอกเว็บแอป ไม่ได้อยู่ในภาพ)

## 7. ข้อจำกัดที่ต้องรักษา (เพื่อให้เอาไปใช้ต่อได้)

- **เทคโนโลยี:** Next.js 16 + Tailwind v4 + shadcn/ui (base-ui) + `lucide-react` **ห้ามเพิ่ม dependency** ถ้าจำเป็นต้องมี ให้บอกเหตุผล
- **ใช้ token เท่านั้น** ห้ามฝังค่าสี ถ้าต้องการสีใหม่ ให้เสนอเป็น token ใน `globals.css` พร้อมคู่สีตัวหนังสือที่ **คอนทราสต์ ≥ 4.5:1** (ค่าปัจจุบันบันทึกไว้ใน `tokens.md`)
- **พฤติกรรมคงเดิม:** ไม่เปลี่ยนว่าอะไรกดแล้วเกิดอะไร ไม่เปลี่ยนลำดับขั้นตอนจอง ไม่ย้ายข้อมูลข้ามหน้า (หน้ารายการเก็บ `name` `sort` `page` ไว้ใน URL ต้องคงไว้)
- **ปุ่มกดได้ง่ายบนมือถือ:** ควรสูงอย่างน้อย 40px (ปุ่มขนาด small ตอนนี้ 34px ใช้ในการ์ดและแถวจัดการ ถ้าจะปรับก็ได้)
- **ข้อความไทยที่ระบบตรวจสอบอัตโนมัติอยู่** ถ้าจะเปลี่ยนต้องแจ้งก่อน เพราะต้องแก้สคริปต์ทดสอบตามด้วย:
  `ดูช่วงว่างแล้วจองได้ทันที`, `ค้นหา`, `จองโต๊ะ`, `จองสำเร็จ`, `ที่นั่งไม่พอสำหรับช่วงเวลานี้`, `เหลือ N ที่`, `ยืนยันแล้ว`, `ยกเลิกแล้ว`, `ยังไม่มีการจอง`, `ไม่พบร้านที่ค้นหา`, `เข้าสู่ระบบ`, `ออกจากระบบ`
  ส่วนข้อความอื่นแก้ได้ แต่ขอให้เสนอเป็นรายการแยก
- **ยังไม่ต้องทำ:** โหมดมืด, หน้า login ของ Keycloak, แอปมือถือ, ภาษาอังกฤษทั้งเว็บ

## 8. สิ่งที่อยากได้กลับมา

1. ภาพออกแบบของแต่ละหน้าใน section 3 ทั้ง **เดสก์ท็อป (1200px) และมือถือ (390px)** รวมสถานะใน section 4
2. **รายการ token ที่เปลี่ยน** ใช้ชื่อเดิมใน `tokens.md` (ค่าเก่า → ค่าใหม่) และ token ใหม่ถ้ามี
3. **สเปกของ component ที่ออกแบบใหม่:** หัวเว็บ, การ์ดร้าน, ช่องช่วงเวลา (ทุกสถานะ), การ์ดสถิติ, EmptyState/ErrorAlert/Skeleton, ฟอร์มจอง
4. รายการ "สิ่งที่ต้องเพิ่ม" แยกต่างหาก (primitive ใหม่ ข้อมูลที่ไม่มีใน backend ข้อความที่เสนอให้เปลี่ยน)
5. ถ้าเป็นไปได้ ให้เรียงลำดับว่าควรทำหน้าไหนก่อน (หน้าที่กรรมการเห็นก่อนคือ landing → หน้าแรก → หน้าร้าน → จอง)
